# Design log

Each decision, why it was made, and the public source it rests on. The panel was designed from a written behaviour spec plus public documentation; no other code was used.

## Floor plan

| #   | Decision                                                                                                                                                                                                                                                         | Why                                                                                                                                                                           | Source                                                                                                                                                                  |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D5  | Zones are marked with a bracketed tag at the end of the object label: `Name [zone]`, `Name [zone title]`, `Name [zone readout]`. Hand-written SVG can use `data-zone`, `data-zone-title`, `data-zone-readout`. The tag word and the label attribute are options. | Inkscape's Object Properties dialog edits the label directly, so authors never touch XML. A label is free text, so names may hold spaces, dots and brackets; XML ids may not. | Inkscape keyboard reference (Ctrl+Shift+O, Object Properties): https://inkscape.org/doc/keys.html; https://developer.mozilla.org/docs/Web/HTML/Global_attributes/data-* |
| D6  | Parse with `DOMParser` (`image/svg+xml`), copy each mark onto a `data-cfm-*` attribute, then sanitise.                                                                                                                                                           | Marks are read before the sanitiser drops editor namespaces; afterwards the panel only relies on its own attributes, never on CSS-escaped names.                              | https://developer.mozilla.org/docs/Web/API/DOMParser                                                                                                                    |
| D7  | Sanitise with DOMPurify (SVG profiles), plus: no `script`, `foreignObject`, `style`, `image`, `a`, `title`, animation elements; only `#id` references in `href` and `url()`. `<use>` is allowed back in for Inkscape clones, safe because of the reference rule. | Maintained sanitiser; `<style>` would leak to the whole page; `<title>` causes native tooltips on top of the panel's own. Licence MPL-2.0 OR Apache-2.0, compatible with MIT. | https://github.com/cure53/DOMPurify                                                                                                                                     |
| D8  | Every id in the plan gets a per-panel prefix from React `useId`, and every `url(#…)` and `href="#…"` reference is rewritten.                                                                                                                                     | SVG ids are global to the page; two panels showing the same plan would otherwise share gradients and clip paths.                                                              | https://developer.mozilla.org/docs/Web/SVG/Attribute/id, https://react.dev/reference/react/useId                                                                        |
| D9  | The plan is parsed only when the markup or the marking options change (`useMemo`), and inserted into the page once per plan. Data refreshes only restyle zones.                                                                                                  | Plans can be over 1 MB.                                                                                                                                                       | Measurements in "Performance" below                                                                                                                                     |

## Data

| #   | Decision                                                                                                                                                                                                                                | Why                                                                                                                             | Source                                                                                                                                        |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| D10 | Three layouts: wide rows with a sensor column; long series with the sensor in labels and the metric in a column, a label or the series name; a ready-made index. A frame with a sensor-key column is read as rows, otherwise as series. | Covers SQL, Flux and pipelines that compute the index upstream. Flux returns `_field`/`_value` and puts group keys into labels. | https://grafana.com/developers/plugin-tools/key-concepts/data-frames, https://docs.influxdata.com/influxdb/v2/reference/syntax/annotated-csv/ |
| D11 | Field roles are found by Grafana field type plus a short list of common names, compared without case and separators. A role chosen in the options must match a field name exactly and is never silently replaced by detection.          | Works without setup for common schemas; a wrong manual choice stays visible.                                                    | Grafana `addFieldNamePicker` option editor                                                                                                    |
| D12 | Newest value per sensor and metric, by time; the last row when there is no time. Sensors in several frames merge by key.                                                                                                                | Long layouts deliver temperature and humidity as separate series with their own times.                                          | Spec requirement                                                                                                                              |
| D13 | Text, `null`, `NaN` and infinite values count as missing.                                                                                                                                                                               | Spec requirement.                                                                                                               |                                                                                                                                               |

## Index and colour

| #   | Decision                                                                                                                                                                                                                                                                                           | Why                                                                                                                                     | Source                                                                                                                                                                                                                                                       |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D14 | "Position in band" (default): 0 at the low limit, 50 mid-band, 100 at the high limit, clamped; mean of the metrics.                                                                                                                                                                                | Spec requirement. The tooltip shows each metric's position so a cancelled-out mean is visible.                                          | Spec                                                                                                                                                                                                                                                         |
| D15 | "Distance outside band": 0 inside, rising linearly outside, 100 at one band width outside; the zone takes the worst metric.                                                                                                                                                                        | A good-to-bad scale where a hot, dry room cannot average out to normal.                                                                 | Own design                                                                                                                                                                                                                                                   |
| D16 | Default band 20–26 °C.                                                                                                                                                                                                                                                                             | EN 16798-1:2019, Category II default design values: 20 °C minimum in the heating season, 26 °C maximum in the cooling season (offices). | EN 16798-1:2019, Annex B default design values (standard text, not free); public overview of the standard: https://www.rehva.eu/rehva-journal/chapter/indoor-environmental-input-parameters-for-the-design-and-assessment-of-energy-performance-of-buildings |
| D17 | Default band 30–60 %RH.                                                                                                                                                                                                                                                                            | US EPA: keep indoor relative humidity below 60 %, ideally between 30 % and 50 %.                                                        | https://www.epa.gov/mold/brief-guide-mold-moisture-and-your-home                                                                                                                                                                                             |
| D18 | Data limits are used only as a valid pair (both numeric, low below high); otherwise the defaults apply and the tooltip says why.                                                                                                                                                                   | Spec requirement.                                                                                                                       |                                                                                                                                                                                                                                                              |
| D19 | Colours come from Grafana's standard colour options with the index mapped to 0–100. Continuous mode asks the field colour mode for the colour at index/100; banded mode uses `getActiveThreshold` on the user's steps. Defaults: blue-yellow-red scheme; steps blue / green from 10 / red from 90. | No colour picker or colour library of our own; thresholds behave as everywhere else in Grafana.                                         | `fieldColorModeRegistry`, `getActiveThreshold` in `@grafana/data`                                                                                                                                                                                            |
| D20 | Solid fill with an opacity option (default 0.8). Colour changes fade with a CSS `transition` on `fill` (450 ms), switched off by an option or by `prefers-reduced-motion`.                                                                                                                         | No timers to clean up; the browser interpolates.                                                                                        | https://developer.mozilla.org/docs/Web/CSS/@media/prefers-reduced-motion                                                                                                                                                                                     |
| D21 | Offline and stale zones get the theme's strong border colour as fill, the theme error colour on title and readout, and a text marker (`offline` / `stale`). Text gets a thin halo in the theme background colour (`paint-order: stroke`).                                                          | State is never shown by colour alone; text stays readable on any fill in both themes.                                                   | https://developer.mozilla.org/docs/Web/SVG/Attribute/paint-order                                                                                                                                                                                             |

## Interaction

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                         | Why                                                                                        | Source                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| D22 | Tooltip rendered with Grafana's `Portal`, `position: fixed`, placed next to the pointer and flipped to stay inside the viewport; content is React text only.                                                                                                                                                                                                                                     | Panels sit inside transformed grid items, where fixed positioning without a portal breaks. | `@grafana/ui` Portal                                                                                                                          |
| D23 | Detail link tokens `${__zone.name}`, `${__zone.sensor}`, `${__zone.label}`, in the `${__…}` style of Grafana data links. Values are encoded with `encodeURIComponent` (which also encodes `$`, so a value cannot inject a variable), then `replaceVariables` fills dashboard variables. The result must parse as `http:`/`https:` or relative via `new URL`. New tab uses `noopener,noreferrer`. | Spec requirement; the URL parser catches tricks such as tabs inside `javascript:`.         | https://grafana.com/developers/plugin-tools/how-to-guides/panel-plugins/interpolate-variables, https://developer.mozilla.org/docs/Web/API/URL |
| D24 | Clickable zones get `tabindex="0"`, `role="link"`, an `aria-label` with the state, a focus ring, and open on Enter or Space.                                                                                                                                                                                                                                                                     | Keyboard access.                                                                           | https://www.w3.org/WAI/ARIA/apg/patterns/link/                                                                                                |
| D25 | Staleness threshold off by default (0). When set, a 30 s clock re-evaluates ages, and only while a threshold is set or a tooltip is open.                                                                                                                                                                                                                                                        | With a past time range every reading is old; on by default would show every room offline.  | Own reasoning                                                                                                                                 |

## Binding editor

| #   | Decision                                                                                                                                                                          | Why                                                                                                | Source          |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------- |
| D26 | Saved as an object `{ zone name: sensor key }`. One sensor per zone; one sensor may feed several zones.                                                                           | Keyed by zone, so a zone's row maps to one value; renaming a sensor label does not break anything. | Own design      |
| D27 | Picker options sorted by label then key with a numeric-aware collator; a saved sensor missing from the data stays visible as "… (not in current data)".                           | Stable order when rows arrive; a binding is never hidden.                                          | `Intl.Collator` |
| D28 | "Bind by matching names" binds each unbound zone to the sensor whose label equals the zone name (case-insensitive); a second button removes bindings of zones that left the plan. | Fast setup for well-labelled data.                                                                 | Own design      |

## Performance

Plan of 1.1 MB with 40 zones and 260 text spans (`src/__fixtures__/bigPlan.ts`), every zone changing on every refresh:

| Environment                                                                                   | Parse and sanitise (once per plan change) | Insert into page | Refresh, median | Refresh, slowest |
| --------------------------------------------------------------------------------------------- | ----------------------------------------- | ---------------- | --------------- | ---------------- |
| Headless Chromium 156, 2 vCPU arm64 VM under load                                             | 350–430 ms                                | 21 ms            | 4.0–4.6 ms      | 29 ms            |
| jsdom (unit test `src/render/performance.test.ts`, 10 refreshes, a quarter of zones changing) | about 6 s                                 | n/a              | n/a             | 13 ms            |

Refreshes stay under the 50 ms budget. Parsing is the expensive step, so it only runs when the plan or its marking settings change.

## Tests

- Unit tests cover the index (limits from data versus defaults, invalid limits, one metric, clamping), all three layouts, newest-reading choice, zone discovery with awkward names, sanitising, id prefixing, link encoding and scheme checks, legend wording, and the DOM writer (only changed zones are touched, original look restored).
- Component tests cover every panel state, tooltip content, click and keyboard activation, the staleness clock and its cleanup, and two panels on one page.
- Playwright tests run the demo dashboards in a real Grafana.
- `jest-setup.js` swaps Node's `MessageChannel` for a timer-based one: React 19's scheduler otherwise keeps a message port open and Jest never exits.
